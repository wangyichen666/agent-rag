## 2. 原理铺垫

### 2.1 中间件 = 洋葱模型

Agent 的生命周期有几个关键环节：reply（整次回复）、reasoning（推理）、acting（执行工具）、model_call（调模型）、compress_context（压缩）、system_prompt（取系统提示）。中间件让你**在这些环节前后插入逻辑，不动 Agent 内核**。

像洋葱：请求一圈圈穿过中间件到达内核，响应再一圈圈穿出。每个中间件可决定"前处理 / 调下一层 / 后处理"。框架内置中间件：`RAGMiddleware`（检索注入）、`TracingMiddleware`（OTel 打点）、`ReplyBudgetControlMiddleware`（预算控制）、`TTSMiddleware`、`AgenticMemoryMiddleware`/`Mem0Middleware`/`ReMeMiddleware`（长期记忆）。

你 W04 看到构造器把 middlewares 按 `is_implemented` 筛到六个列表（`_agent.py:170-188`）——只实现 `on_reasoning` 的只在推理时穿，省开销。

### 2.2 记忆三层架构

```
短期记忆  = AgentState.context（消息历史，每轮喂给模型）
   ↑ 超 trigger_ratio(0.8) 触发
上下文压缩 = 把旧历史压成 SummarySchema 结构化摘要，替换 context
   ↑ 需要跨 session 记住？
长期记忆  = AgenticMemory(文件MD) / Mem0 / ReMe 三选一
```

关键洞察：**压缩不是截断，是结构化总结**。它让模型生成 `task_overview/current_state/important_discoveries/next_steps/context_to_preserve` 五个字段，把"做了什么、发现了什么、下一步"存下来——比单纯砍尾巴聪明得多，这是它能长程不漂的关键。

### 2.3 Trace + Token 监控

- **Trace**：`TracingMiddleware` 基于 OpenTelemetry，产出 agent/llm/tool 三类 span，能可视化"一次回复里调了几次模型、几次工具、各耗多久"。生产排查必备。
- **Token**：每条 `Msg.usage` 带 `input_tokens/output_tokens`；`ReplyBudgetControlMiddleware` 按预算熔断。W10 QwenPaw 的 `token_usage/` 把它加厚成监控系统。

## 3. 源码精读

### 3.1 六大 hook（`middleware/_base.py`）

`MiddlewareBase`（`:12`）定义六个可重写 hook：

| Hook | 行号 | 拦截环节 |
|---|---|---|
| `on_reply` | `:65` | 整次回复（最外层洋葱） |
| `on_reasoning` | `:91` | 推理（调模型） |
| `on_acting` | `:114` | 执行工具 |
| `on_model_call` | `:160` | 单次模型调用 |
| `on_compress_context` | `:188` | 上下文压缩 |
| `on_system_prompt` | `:211` | 取系统提示（transformer 模式） |

每个 hook 拿到 `next_handler`，调它就进入下一层洋葱。Agent `__init__` 按 `is_implemented` 把中间件筛到对应列表（`_agent.py:171-188`）。

### 3.2 上下文压缩 `_compress_context_impl`（`_agent.py:327`）

这是 W03"上下文爆炸"痛点的解药，精读（subagent 已确认行号）：

- `:344` 取 `ContextConfig`。
- `:351` **触发阈值**：`threshold = cfg.trigger_ratio * self.model.context_size`。`trigger_ratio` 默认 0.8——上下文占满 80% 才压。
- `:352-353` 低于阈值直接 return，不压（省 token）。
- `:382` 按 `reserve_ratio`（默认 0.1，留 10%）把 context 切成"要压的/要留的"两段（`_split_context_for_compression`）。
- `:437-448` **把 SummarySchema 包装成一个"工具"**，让模型"调用"它来产出结构化摘要——巧妙复用 Function Calling 机制做结构化输出。
- `:465` 调 `self.model.generate_structured_output(messages, structured_model=cfg.summary_schema)` 拿结构化摘要。
- `:470-509` **溢出兜底**：万一压不动（输入太大），逐步丢最旧的消息直到能压，保证至少留 `(1-trigger_ratio)` 空间。
- `:520` `new_summary = cfg.summary_template.format(**res.content)`——用模板把五字段渲染成摘要文本。
- `:536-537` 落地：`self.state.summary = new_summary` + `self.state.context = msgs_to_reserve`。
- 在 `_reply_impl:759`，每轮推理前 `await self.compress_context()`——边跑边压。

### 3.3 `SummarySchema`（`_config.py:9`）

五字段：`task_overview`（核心请求与成功标准）、`current_state`（已完成+产出）、`important_discoveries`（约束/决策/踩过的坑）、`next_steps`（待办+阻塞）、`context_to_preserve`（用户偏好/承诺）。压的不是"聊天记录摘要"，是"任务进度档案"。

### 3.4 ContextConfig 关键字段（`_config.py:51`）

`trigger_ratio=0.8`、`reserve_ratio=0.1`、`tool_result_limit=50000`（工具结果超 5 万 token 截断，治 W03 第二个痛点）、`compression_prompt`、`summary_template`、`summary_schema`。

### 3.5 内置中间件

| 中间件 | 位置 | 作用 |
|---|---|---|
| `RAGMiddleware` | `middleware/_rag.py:456` | RAG 注入（W08 详讲） |
| `TracingMiddleware` | `middleware/_tracing/_trace.py:116` | OTel 打点（agent/llm/tool span），属性在 `_tracing/_attributes.py` |
| `ReplyBudgetControlMiddleware` | `middleware/_budget.py:21` | 回复预算熔断 |
| `TTSMiddleware` | `middleware/_tts_middleware.py:21` | 文本转语音 |
| `AgenticMemoryMiddleware` | `middleware/_longterm_memory/_agentic_memory/_middleware.py:208` | 文件系统 MD 长期记忆 |
| `Mem0Middleware` | `middleware/_longterm_memory/_mem0/_middleware.py:86` | 接 mem0，跨 session |
| `ReMeMiddleware` | `middleware/_longterm_memory/_reme/_middleware.py:85` | 嵌入 reme-ai，后台自动记+检索 |

### 3.6 三种长期记忆怎么选

- **AgenticMemory**：Agent 自己读写工作目录下的 `Memory/MEMORY.md` + 主题文件。**零外部依赖**，最易上手，透明可控。
- **Mem0**：接 mem0 服务，跨 session 记忆，适合多用户共享。
- **ReMe**：嵌入式，后台自动记 + 向量检索，省心但黑盒。

### 作业 1：写一个审计中间件

`code/w07/audit_middleware.py`：实现 `on_reasoning`，记录每次推理的迭代号 + token。

```python
# code/w07/audit_middleware.py
import asyncio, os
from agentscope.agent import Agent
from agentscope.credential import DashScopeCredential
from agentscope.message import UserMsg
from agentscope.middleware import MiddlewareBase
from agentscope.model import DashScopeChatModel
from agentscope.tool import Bash, Toolkit

class AuditMiddleware(MiddlewareBase):
    """记录每次推理的迭代号与 token 用量。"""
    async def on_reasoning(self, *, agent, input_kwargs, next_handler):
        # 前处理
        print(f"  📝 [audit] reasoning iter={agent.state.cur_iter}")
        # 调下一层洋葱(真正的推理)
        result = []
        async for item in next_handler(**input_kwargs):
            result.append(item)
            yield item
        # 后处理
        last = agent.state.context[-1] if agent.state.context else None
        usage = getattr(last, "usage", None) if last else None
        print(f"  📝 [audit] done usage={usage}")

async def main():
    model = DashScopeChatModel(
        credential=DashScopeCredential(api_key=os.environ["DASHSCOPE_API_KEY"]),
        model="qwen-plus", stream=True)
    agent = Agent(
        name="audit", system_prompt="你是助手", model=model,
        toolkit=Toolkit(tools=[Bash()]),
        middlewares=[AuditMiddleware()],  # plug 进去
    )
    async for e in agent.reply_stream(UserMsg("u", "看下当前目录文件")):
        if e.type.value == "text_block_delta":
            print(e.text_delta, end="", flush=True)
    print()

asyncio.run(main())
```

**预期**：每次推理前后打印 `[audit]` 行，含迭代号和 token 用量。体会"不动 Agent 源码就加了审计"——这是中间件的核心价值。

## 5. 面试问答卡

**Q1：上下文压缩什么时候触发？怎么压？为什么会结构化？**
- 参考答案：`_reply_impl:759` 每轮推理前调 `compress_context`，在 `_compress_context_impl:327` 里，当 token 超 `trigger_ratio(0.8) * context_size`（`:351`）触发；按 `reserve_ratio(0.1)` 切分（`:382`）；把 `SummarySchema`（五字段：任务/状态/发现/下一步/保留）包装成工具，调 `generate_structured_output`（`:465`）拿结构化摘要；`summary_template.format`（`:520`）渲染后替换 `state.summary` + `state.context`（`:536-537`）。结构化是为了不丢"任务进度"，比截断尾巴聪明。
- 话术：「超 80% 触发，按 SummarySchema 五字段让模型出任务进度档案，替换旧历史。」

**Q2：三层记忆怎么分？**
- 参考答案：短期=`AgentState.context`（消息历史）；压缩=超阈值压成 SummarySchema 摘要；长期=AgenticMemory(文件 MD，零依赖)/Mem0(跨 session)/ReMe(嵌入式自动记+检索)。选择看是否跨 session、是否要透明可控。
- 话术：「短期是历史，压缩是进度档案，长期三选一看跨不跨 session。」

**Q3：中间件的洋葱模型是什么？怎么用？**
- 参考答案：六个 hook（`_base.py` 的 on_reply/reasoning/acting/model_call/compress_context/system_prompt）把 Agent 生命周期包成洋葱，中间件前处理→调 `next_handler`→后处理。构造器按 `is_implemented` 筛到六个列表（`_agent.py:171-188`）省开销。plug 进 `middlewares=[]` 即用，不动内核。
- 话术：「洋葱六 hook，plug 中间件就改行为，内核不动。」

**Q4：Trace 和 Token 监控怎么做？**
- 参考答案：`TracingMiddleware`（`_tracing/_trace.py:116`）基于 OpenTelemetry 产 agent/llm/tool span；每条 `Msg.usage` 带 input/output token；`ReplyBudgetControlMiddleware`（`_budget.py:21`）按预算熔断。W10 QwenPaw `token_usage/` 把它加厚成监控系统。
- 话术：「TracingMiddleware 出 span，Msg.usage 出 token，预算中间件管熔断。」
