# 04 数据库与存储设计

> 三类存储各管各的：
> **MySQL** = 业务事实（用户、知识库、文档状态、会话消息）
> **MinIO** = 原始文件
> **Milvus** = 向量与 chunk 原文（检索用）
>
> 一致性原则：MySQL 是事实源；向量库内容可由 MySQL + MinIO 重建（rebuild 能力必须保留）。

## 1. MySQL 表设计

### 1.1 用户与权限

```sql
CREATE TABLE sys_user (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    username      VARCHAR(64)  NOT NULL UNIQUE,
    password_hash VARCHAR(128) NOT NULL,
    nickname      VARCHAR(64),
    role          VARCHAR(32)  NOT NULL DEFAULT 'user',   -- admin / user
    status        TINYINT      NOT NULL DEFAULT 1,
    created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 知识库级授权（决策点 3 确认后启用；一期可简化为 admin 全权 + user 只读指定库）
CREATE TABLE kb_permission (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    kb_id        BIGINT      NOT NULL,
    subject_type VARCHAR(16) NOT NULL,     -- user / role / dept
    subject_id   BIGINT      NOT NULL,
    perm         VARCHAR(16) NOT NULL,     -- read / write / owner
    UNIQUE KEY uk_kb_subject (kb_id, subject_type, subject_id)
);
```

### 1.2 知识库与文档

```sql
CREATE TABLE kb (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    kb_code         VARCHAR(64) NOT NULL UNIQUE,   -- 传给 Python 的 kb_id
    name            VARCHAR(128) NOT NULL,
    description     VARCHAR(512),
    embedding_model VARCHAR(64) NOT NULL DEFAULT 'bge-m3',
    chunk_config    JSON,        -- {strategy, chunk_size, chunk_overlap, parent_child}
    owner_id        BIGINT      NOT NULL,
    status          TINYINT     NOT NULL DEFAULT 1,
    created_at      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE kb_document (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    doc_code     VARCHAR(64) NOT NULL UNIQUE,      -- 传给 Python 的 doc_id
    kb_id        BIGINT      NOT NULL,
    file_name    VARCHAR(255) NOT NULL,
    file_type    VARCHAR(16)  NOT NULL,            -- pdf / docx / md / xlsx
    file_size    BIGINT,
    file_hash    CHAR(64),                          -- sha256，秒传与去重
    minio_path   VARCHAR(512) NOT NULL,
    parse_status VARCHAR(16) NOT NULL DEFAULT 'pending',
                 -- pending / parsing / success / failed
    chunk_count  INT          NOT NULL DEFAULT 0,
    error_msg    TEXT,
    version      INT          NOT NULL DEFAULT 1,   -- 重新上传/重建时 +1
    created_by   BIGINT,
    created_at   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_kb_status (kb_id, parse_status),
    KEY idx_hash (file_hash)
);
```

文档状态机：

```
pending --(提交 ingest 任务)--> parsing --(回调 success)--> success
                                  |
                                  +--(回调 failed)--> failed --(重新解析)--> parsing
```

### 1.3 会话与消息

```sql
CREATE TABLE conversation (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT      NOT NULL,
    kb_ids      JSON        NOT NULL,      -- 本会话勾选的知识库
    title       VARCHAR(255),              -- 首轮问题截断生成，或 LLM 总结
    created_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_user (user_id, updated_at)
);

CREATE TABLE message (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    conversation_id BIGINT      NOT NULL,
    role            VARCHAR(16) NOT NULL,   -- user / assistant
    content         MEDIUMTEXT  NOT NULL,
    rewritten_query VARCHAR(1024),          -- 改写后的检索 query（调试用）
    citations       JSON,                   -- 引用列表（见 03 文档 meta 事件）
    retrieval_debug JSON,                   -- rerank 分数、命中数等（观测用）
    prompt_tokens   INT,
    completion_tokens INT,
    latency_ms      INT,
    feedback        TINYINT,                -- 1 赞 / -1 踩 / NULL
    feedback_note   VARCHAR(512),
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY idx_conv (conversation_id, id)
);
```

> `retrieval_debug` 与 `feedback` 是 02 文档第 10 节「质量评估飞轮」的数据来源，**必须落库**。

## 2. MinIO 桶设计

```
桶：rag-docs
├── kb_01/
│   ├── d_123/v1/系统设计说明书.pdf      # version 入路径，避免覆盖
│   └── d_124/v1/部署手册.pdf
└── kb_02/ ...
```

- 路径规则：`{kb_code}/{doc_code}/v{version}/{原始文件名}`
- 生命周期：文档删除后文件保留 30 天（lifecycle 规则）再物理清除，防止误删
- 访问：Java 生成预签名 URL 给 Python 拉取（内网也可直接走 SDK）

## 3. Milvus Collection 设计

Collection：`rag_chunks`（全系统单 collection，按知识库分区）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INT64, PK, auto_id | 主键 |
| `kb_id` | VARCHAR(64) | **Partition Key**，知识库物理隔离 |
| `doc_id` | VARCHAR(64) | 文档标识，删除/重建按它过滤 |
| `chunk_id` | VARCHAR(64) | 业务 chunk 标识（doc_id + index + version） |
| `parent_id` | VARCHAR(64) | 父子分块；未启用则为空 |
| `content` | VARCHAR(8192) | chunk 原文（检索后直接取回，免回查） |
| `metadata` | JSON | title_path / page / source_file / content_type |
| `dense` | FLOAT_VECTOR(1024) | BGE-M3 稠密向量，HNSW + IP（归一化） |
| `sparse` | SPARSE_FLOAT_VECTOR | BGE-M3 稀疏向量，SPARSE_INVERTED_INDEX + IP |

索引参数（初始值，按评测调）：

```python
dense_index  = {"index_type": "HNSW", "metric_type": "IP",
                "params": {"M": 16, "efConstruction": 200}}
sparse_index = {"index_type": "SPARSE_INVERTED_INDEX", "metric_type": "IP"}
search_ef    = 64   # 查询期参数，≥ dense_top_k
```

容量估算（供决策点 2 参考）：

```
单 chunk 存储 ≈ dense 1024×4B + 原文 ~1.5KB + 稀疏/元数据 ≈ 约 6~8KB（含索引放大）
100 万 chunk ≈ 7~8GB 内存（HNSW 需全量加载内存）
```

## 4. 一致性保障

| 操作 | 顺序 | 理由 |
|---|---|---|
| 新增文档 | MySQL 记录 → MinIO 上传 → Python ingest（异步）→ 回调更新状态 | 任何一步失败都有明确状态可查 |
| 删除文档 | 删向量 → 删 MySQL 记录 → MinIO 延迟清除 | 先断检索入口，残留文件无害 |
| 更新文档 | 新版本入库成功 → 删旧版本向量 → 更新记录 version | 检索不中断，短暂新旧并存可接受 |
| 知识库删除 | 确认 → 删分区 → 删 MySQL → MinIO 延迟清除 | 二次确认，不可逆操作 |

## 5. Redis（可选，二期）

- 检索结果缓存：`ret:{kb_id}:{sha256(query)}` → top chunks，TTL 10 分钟
- 会话级限流计数
