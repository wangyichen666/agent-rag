# 03 服务接口设计

> 定义三类接口契约：
> A. **Java ↔ Python**（内部接口，本文档重点，需双端严格对齐）
> B. **前端 ↔ Java**（业务接口，概述）
> C. 统一错误码
>
> 约定：Python 侧以 FastAPI + Pydantic 定义 schema 为准，Java 侧 `AiClient` 镜像字段；所有内部接口带 Header `X-Internal-Token`。

---

## A. Java → Python 内部接口

Base URL：`http://agent-rag-python:8000`

### A.1 流式问答（核心接口）

`POST /v1/chat/completions`

**Request**

```json
{
  "session_id": "s_20260726_001",
  "kb_ids": ["kb_01", "kb_02"],
  "question": "vLLM 部署需要多少显存？",
  "history": [
    {"role": "user", "content": "本地部署大模型有哪些方案？"},
    {"role": "assistant", "content": "主要有 vLLM、Ollama..."}
  ],
  "options": {
    "stream": true,
    "rewrite_query": true,
    "dense_top_k": 20,
    "sparse_top_k": 20,
    "rerank_top_n": 5,
    "score_threshold": 0.35,
    "temperature": 0.1,
    "max_tokens": 1024
  }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `kb_ids` | Java 已做权限过滤后的知识库列表；Python 检索时强制过滤 |
| `history` | Java 侧截取好的最近 N 轮；Python 用于指代消解改写 |
| `options.score_threshold` | rerank 归一化分数阈值，全低于则走拒答 |

**Response**：`Content-Type: text/event-stream`

```
event: meta
data: {"session_id":"s_20260726_001","rewritten_query":"vLLM 部署的显存需求","citations":[{"ref_id":1,"doc_id":"d_123","source_file":"部署手册.pdf","page":42,"title_path":["第三章","3.2 架构"],"chunk_id":"c_9f"}],"no_relevant_context":false}

event: token
data: {"delta":"根据部署手册"}

event: token
data: {"delta":"，vLLM 的"}

event: done
data: {"finish_reason":"stop","usage":{"prompt_tokens":2430,"completion_tokens":356},"latency_ms":1830,"retrieval":{"dense_hits":20,"sparse_hits":19,"rerank_scores":[0.87,0.71,0.66,0.41,0.38]}}
```

拒答场景（`no_relevant_context: true`）：`meta` 后直接 `done`，`token` 事件缺省或由 Python 发固定话术。

**事件类型**

| event | 时机 | data |
|---|---|---|
| `meta` | 首包 | 改写后 query、引用列表、是否拒答 |
| `token` | 逐 token | `{"delta": "..."}` |
| `done` | 结束 | token 用量、耗时、检索中间结果（供 Java 落库审计） |
| `error` | 异常 | `{"code": "...", "message": "..."}` |

### A.2 纯检索（调试/测试/召回验证）

`POST /v1/retrieve`

```json
{
  "kb_ids": ["kb_01"],
  "query": "vLLM 显存需求",
  "dense_top_k": 20,
  "sparse_top_k": 20,
  "rerank_top_n": 5
}
```

**Response**

```json
{
  "results": [
    {
      "chunk_id": "c_9f",
      "content": "vLLM 部署 Qwen2.5-14B 需要...",
      "rerank_score": 0.87,
      "dense_rank": 3,
      "sparse_rank": 1,
      "metadata": {"doc_id": "d_123", "source_file": "部署手册.pdf", "page": 42}
    }
  ]
}
```

用途：前端「召回测试」页（知识库管理后台里调试验证解析切分质量），以及离线评测脚本。

### A.3 文档解析入库

`POST /v1/ingest`（异步，返回 202）

```json
{
  "kb_id": "kb_01",
  "doc_id": "d_123",
  "file": {
    "url": "http://minio:9000/rag-docs/kb_01/d_123/系统设计说明书.pdf",
    "name": "系统设计说明书.pdf",
    "type": "pdf"
  },
  "parser": "fast",
  "chunk_config": {
    "strategy": "structure",
    "chunk_size": 512,
    "chunk_overlap": 64,
    "parent_child": false
  },
  "callback_url": "http://agent-rag-java:8080/internal/callback/ingest"
}
```

**Response 202**

```json
{"doc_id": "d_123", "task_id": "t_abc", "status": "processing"}
```

完成/失败后 Python 回调 `callback_url`：

```json
{
  "doc_id": "d_123",
  "status": "success",
  "chunk_count": 87,
  "elapsed_ms": 42000,
  "error": null
}
```

> Java 侧据此更新 `kb_document.parse_status`（`pending → parsing → success / failed`）。
> 兜底：Java 也可轮询 `GET /v1/ingest/status/{task_id}`。

### A.4 文档删除（向量清理）

`POST /v1/documents/delete`

```json
{"kb_id": "kb_01", "doc_id": "d_123"}
```

按 `doc_id` 表达式从向量库删除全部 chunk。Java 在删除文档记录前先调本接口，成功后再删业务记录与 MinIO 文件（顺序保证：宁可残留文件，不可残留可被检索到的向量）。

### A.5 知识库向量空间管理

| 接口 | 说明 |
|---|---|
| `POST /v1/kb/create` | `{"kb_id": "kb_01"}`，按 kb 建分区/collection |
| `POST /v1/kb/delete` | 删除整个知识库向量数据（不可恢复，Java 侧需二次确认） |
| `POST /v1/kb/rebuild` | 重建索引（切分策略升级后重刷全库，异步任务） |

### A.6 健康检查

`GET /healthz`

```json
{
  "status": "ok",
  "components": {
    "vector_store": "ok",
    "embedding_model": "ok",
    "reranker": "ok",
    "llm": "ok"
  },
  "models": {"embedding": "bge-m3", "reranker": "bge-reranker-v2-m3", "llm": "deepseek-chat"}
}
```

Java 启动探活 + 前端「系统状态」页使用。

## B. 前端 ↔ Java 业务接口（概述）

Base URL：`/api`，认证：**免登录模式**（后端不校验 JWT，业务统一使用管理员账号 id=1；
JWT 相关代码已移除，可参照 git 历史恢复）

| 模块 | 接口 | 说明 |
|---|---|---|
| 知识库 | `GET/POST /kb`、`PUT/DELETE /kb/{id}` | CRUD |
| 文档 | `POST /kb/{id}/documents`（multipart 上传） | Java 存 MinIO → 调 Python ingest |
| 文档 | `GET /kb/{id}/documents` | 列表，含 parse_status 轮询 |
| 文档 | `DELETE /documents/{id}` | 先删向量再删记录 |
| 召回测试 | `POST /kb/{id}/retrieve-test` | 透传 Python A.2，后台调试页 |
| 会话 | `GET/POST /conversations`、`GET /conversations/{id}/messages` | 历史管理 |
| 问答 | `POST /chat/completions`（SSE） | Java 鉴权 → 调 Python A.1 → 透传；done 时落库 |
| 反馈 | `POST /messages/{id}/feedback` | 赞/踩 + 备注，评测原料 |

前端 SSE 协议与 A.1 完全一致（Java 原样透传事件）。

## C. 统一错误码

SSE `error` 事件与 HTTP 错误响应共用：

| code | HTTP | 含义 | 前端表现 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | JWT 无效/过期 | 跳登录 |
| `KB_FORBIDDEN` | 403 | 无该知识库权限 | 提示无权限 |
| `DOC_PARSE_FAILED` | 200(回调) | 解析失败 | 文档列表标红，可看 error_msg |
| `NO_RELEVANT_CONTEXT` | —(SSE) | 检索无相关内容 | 拒答话术（非错误 UI） |
| `LLM_TIMEOUT` | —(SSE) | 模型超时 | 保留已生成内容 + 重试按钮 |
| `LLM_RATE_LIMITED` | —(SSE) | 模型限流 | 提示稍候 |
| `VECTOR_STORE_ERROR` | 500 | 向量库故障 | 服务维护提示 |
| `INTERNAL_ERROR` | 500 | 兜底 | 通用错误提示 |

Python 侧异常一律捕获后转 `error` 事件，**不允许 SSE 流裸断**（前端无法区分网络断与服务崩）。
