# 10 知识图谱（GraphRAG）设计

> 一期目标：在既有「向量检索 + RRF + Rerank」链路上增加**图谱通道**，解决多跳推理与关系型问题，
> 并提供一个可交互的图谱可视化页面。Neo4j 不可用时**整体降级**，不影响原有问答与入库。

## 1. 数据模型（Neo4j，按 kb_id 分区）

```text
(:Entity {kb_id, name, name_lower, entity_type})
(:Chunk  {kb_id, doc_id, chunk_id, content, source_file, page, title_path})
(e1)-[:RELATES_TO  {kb_id, relation, doc_id}]->(e2)   # LLM 抽取的三元组关系
(e)-[:MENTIONED_IN {kb_id, doc_id}]->(c)              # 实体出处块（可视化 + 检索回填）
```

- 约束：`(kb_id, name)` 与 `(kb_id, chunk_id)` 唯一，入库用 MERGE 保证幂等。
- 同一文档重复入库先 `delete_doc` 再重建；删除文档/知识库会同步清理图谱。
- 孤立实体（没有任何关系/出处块）入库后自动清除。

## 2. 两条链路

### 入库（异步，失败不阻塞向量入库）

```text
chunk → LLM 批量抽取三元组（6 块/批，JSON 契约）
      → 写 Chunk / Entity / RELATES_TO / MENTIONED_IN
```

抽取失败仅告警降级：该文档图谱缺失，向量检索不受影响。

### 问答（图谱通道与向量通道并行）

```text
问题 → LLM 抽取实体名 → Neo4j 精确匹配
     →（未命中则文本包含兜底）→ 子图 1..2 跳扩展
     → 命中块作为 graph 通道 → 与 dense/sparse 做 RRF 融合
     → 原有 Rerank / 阈值 / Prompt / 流式生成
```

`Candidate` 新增 `graph_rank` / `graph_hops`，`RetrievalDebug` 新增 `graph_hits`。

## 3. 接口（Java 代理，JWT 保护）

| 接口 | 说明 |
|---|---|
| `GET /api/kb/{id}/graph?limit=N` | 图谱可视化数据（实体/关系/出处块） |
| `GET /api/kb/{id}/graph/stats` | 实体数 / 关系数 / 出处块数 |

前端「知识图谱」页面基于自研 SVG 力导向布局：缩放/平移/拖节点、点击查看详情、关键词高亮、规模统计。
也可直接访问 Neo4j Browser（http://localhost:7474）查看全量数据。

## 4. 配置（agent-rag-python/.env）

```bash
RAG_GRAPH_ENABLED=true
RAG_NEO4J_URI=bolt://127.0.0.1:7687
RAG_NEO4J_USER=neo4j
RAG_NEO4J_PASSWORD=neo4jrag
RAG_GRAPH_EXTRACT_MODEL=            # 为空复用 RAG_LLM_MODEL
RAG_GRAPH_EXTRACT_BATCH_SIZE=6      # 控制 LLM 成本与单次超限风险
RAG_GRAPH_MAX_HOPS=2
RAG_GRAPH_TOP_K=8
```

Docker Compose 已内置 neo4j 服务，`NEO4J_PASSWORD` 默认 `neo4jrag`（可用环境变量覆盖）。

## 5. 成本与取舍

- **入库成本**：每批 chunk 一次 LLM 抽取调用（DeepSeek），token 成本可控；批量大小可调。
- **延迟**：图检索为本地 Cypher 遍历，毫秒级；抽取实体一次小 LLM 调用（128 token）。
- **能力边界**：不做社区检测/全局摘要（Microsoft GraphRAG 风格）；如需要可二期基于
  RELATES_TO 子图做社区发现，为「整个知识库在讲什么」类问题补全局通道。
- **可视化上限**：接口默认返回 400 节点，超出部分提示去 Neo4j Browser 查看。
